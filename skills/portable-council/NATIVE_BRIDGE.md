# Configurable native JSON bridge

`scripts/native_json_bridge.py` supplies the adapter implementation for the inspected Claude Code JSON result contract. Configure it; no custom Python adapter is needed for that contract. It has **not been run against a live provider** in this public edition. Other providers still require a reviewed adapter. There is no automatic CLI install, login, model lookup, API fallback or latest-model default.

1. Copy `examples/native-bridge.example.json` and your Council configuration outside the repository. Choose a trusted working directory for both. Review its native CLI settings, hooks, tools, plugins and MCP connections. Native config files remain accessible; this is not a sandbox.
2. Replace the executable placeholder with your installed executable (or an explicit trusted interpreter plus CLI script). Check its current `--help` and authenticated non-inference capability/billing surfaces. Copy the exact model and effort into `settings`; do not use the combined `ultracode` effort alias. Optional `modes` supports only `{"ultracode": true/false}` here. Requested settings must exactly equal the Council seat's `requested` object.
3. Review the complete argv against your CLI version and authorization. The example disables tools and uses an empty explicit MCP configuration for an answer-only consultation. If a requested workflow mode needs additional tools, configure only the authorized tools and reverify native compatibility; do not claim that a mode is effective merely because its flag was passed. No tools or mode is enabled by this package on its own.
4. Confirm the same-account subscription, fresh model/mode eligibility and available quota in the Council seat's evidence. Inspect inherited native configuration for paid usage, API routing and automatic fallback; this program cannot certify arbitrary executable code or native auth stores. Only then set `reviewed_native_command=true`, `enabled=true` in the bridge file, and enable the Council seat.
5. Set the seat's `command` to `["YOUR_PYTHON_EXECUTABLE", "ABSOLUTE_PATH_TO_native_json_bridge.py", "--config", "ABSOLUTE_PATH_TO_YOUR_BRIDGE_CONFIG"]`. Use `plan` first, then authorized `ask` through `council.py`. Do not invoke the bridge as a standalone model launcher: it relies on its Council parent's process ownership and passes the parent's bounded timeout to the CLI.

The native command must contain exactly one of each complete argument `{model}`, `{effort}`, `{settings_json}`, immediately following the corresponding native `--model`/`-m`, `--effort`, and `--settings` option. The bridge constructs settings JSON with `fastMode:false` and the supported requested mode. It rejects duplicate/inline overrides, known paid/Fast and permission-bypass flags, `--bare`, model fallback, existing-session continuation, cloud/background dispatch and the `--` option terminator. Argv is never passed through a shell. The question and consultation guard go on stdin; they cannot alter argv. Arbitrary trusted wrapper code can still do anything the user permits, so these checks are not a security boundary around unknown executables.

The bridge accepts a single JSON result or newline-delimited JSON, waits for native process exit, and uses the last successful `type=result`, `subtype=success`, `is_error=false` response with nonempty text. Incomplete stop reasons, malformed/duplicate/non-finite JSON, model disagreement and structured API/overage observations fail. No partial thoughts or tool output are returned. Model/billing observations, when present, come from structured native fields. Missing effort/Fast/mode/billing observations remain null; requested argv is never copied as effective metadata. Native errors are conservative `unknown` failures and are never automatically retried. `cleanup_incomplete:true` is preserved when bounded process cleanup cannot be confirmed.

The parser contract was derived from the local MIT source's native parser. The official [headless documentation](https://code.claude.com/docs/en/headless) and [CLI reference](https://code.claude.com/docs/en/cli-reference), checked 2026-11-02, document print mode, stdin and JSON/stream-JSON output. They also distinguish API-only bare mode from subscription login; this bridge rejects bare mode. These documents describe the interface, not your installed version or account eligibility. No source or test here establishes live compatibility.

## 繁體中文

這個 bridge 提供已檢視的 Claude Code JSON 結果介面轉接，不需自行寫 adapter 程式；本公開版尚未進行真實供應商推論驗證。請把停用的範例複製到倉庫外，指定可信任的原生執行檔、精確模型與 effort，保留 Fast 關閉，並填入已驗證的 Council 原生證據。任一設定不同即拒絕執行。

範例以不使用工具、空 MCP 的純回答工作為起點。若開啟 Ultracode 等模式需要特定工具，必須另行核對原生能力與原有授權；本程式不會因設定布林值便宣稱模式已生效。Bridge 應只由 Council 啟動，以保留父程序的期限與程序樹清理；不可用它繞過登入、訂閱、權限或啟用付費路線。程式會拒絕已知的覆寫／備援／遠端／背景參數，但不可能替未知的使用者執行檔保證行為。CLI 的既有設定及認證來源仍須自行審閱。

只回傳完整原生最終答案，未觀察到的模式或計費欄位保持 null。錯誤不重試，清理未完成會保留標記。其他供應商仍需依 adapter 協定實作與驗證，不可把本機合成程序測試當成跨供應商或帳號測試。
