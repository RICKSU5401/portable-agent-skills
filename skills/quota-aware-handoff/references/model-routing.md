# Model and capability prerequisite

Use a user-controlled routing policy (for example the sibling
`tiered-model-routing` skill) to classify each bounded work unit and select from
fresh, authenticated native capability evidence. No provider family, model ID,
effort level, price, speed mode or fallback is universally current.

Keep requested policy, resolved configuration and observed execution metadata
separate. An instruction file cannot change the current model. Unknown observed
fields remain null; a model's self-description is not native execution evidence.
Pin the selected model before the single handoff launch. The dispatcher only
requires one matching explicit `--model`/`-m` argument: it does not discover
models or validate native effort/context/mode semantics.

For this public dispatcher, native subscription billing and Fast off are required.
An API key or separate vendor API is a different route and is not implemented.
An unavailable family, unknown quota, unsupported mode, timeout or permission
refusal must not silently trigger a model/account/billing change. Preserve user
authorization and single-writer ownership. Any future fallback must be resolved
and evidenced before the one actual launch, never as an automatic retry.
